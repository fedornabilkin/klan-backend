# Бизнес-правила Klan API

Этот документ фиксирует серверные требования. Фактические отчёты ручной приёмки и инфраструктурных проверок хранятся вне репозитория.

## Доступ и профили

- Закрытые данные доступны только авторизованным участникам; сессия обязательна и для WebSocket.
- Членство хотя бы в одной разрешённой Telegram-группе необходимо для входа. Уровень доступа определяется на сервере по группе и числовому Telegram ID.
- Импортированные привязки Telegram ID сохраняются; изменение контактного username не переносит чужую авторизацию.
- Участник редактирует собственный профиль, имя, фамилию, отчество, позывной, дату рождения, контактный username, описание, географию, теги, факты и достижения.
- Факты и достижения допускают дату и редактирование/удаление. Дата рождения и неизвестные сведения не выводятся предположительно.
- Новый тег состоит из одного слова. Повторные имена тегов нормализуются; выбор существующего не создаёт дубликат.
- Публичные числовые ID стабильны. Удалённые ID не выдаются заново.
- Экспорт и импорт собственного профиля не позволяют задать роли, внутренний ID или привязку авторизации.

## Команды, мероприятия, челленджи

- Участник состоит не более чем в одной активной команде. Архивные команды сохраняют историю; повторная активация проверяет инвариант.
- Челлендж сохраняет команду на момент вступления независимо от последующего изменения активной команды.
- Результат принадлежит авторизованному участнику и допустимой календарной дате. Будущие даты, даты вне периода и изменения после завершения запрещены.
- Повторная запись за тот же день обновляет результат, а не добавляет дубликат. Нулевое значение отличается от отсутствия записи.
- Результаты с неизвестной датой не входят в дневные итоги и рейтинги до явного уточнения.
- История результатов препятствует выходу/удалению, которое уничтожило бы её связь с участником или командой.
- Мероприятия проверяют вместимость, участие и предметы из справочника. Количество предметов валидируется сервером.
- Участник может отправить обратную связь и изменить собственный текст; административные изменения статусов требуют соответствующих прав.

## Надёжность и проверки

- Мутации атомарны и создают продуктовую активность после успешной записи.
- Миграции выполняются до запуска HTTP и не повторяют уже применённые версии.
- Ошибки не раскрывают SQL, токены, пароли, URL Telegram с токеном или внутренние клиентские объекты.
- Обязательны проверки отказа гостю, ограничений ролей, CSRF, однократности входа, транзакционного отката и бизнес-инвариантов.
- Production не допускает демонстрационный вход; реальная проверка Telegram требует настроенного бота, группы и HTTPS-сайта.
