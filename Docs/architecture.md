# Архитектура API

Backend — самостоятельное ESM-приложение. Его сборка использует только `Project/src/`, установленные зависимости и публичный географический справочник в `Project/data/`. Импортов из frontend, bot или операционного каталога нет.

## Модули

Модули ниже находятся в `Project/src/`. npm-команды выполняются из `Project/`.

- `app.ts` — HTTP-маршруты, валидация, авторизация, ограничения origin, единый формат ошибок.
- `domain.ts` и профильные модули — операции над участниками, командами, челленджами, справочниками и аналитикой.
- `repository.ts` — PostgreSQL и изолированный файловый/памятный репозиторий для разработки и тестов.
- `auth.ts` — браузерные сессии, одноразовые запросы входа, проверки членства и обработка полученных от bot обновлений.
- `server.ts` — подключение базы, миграции, HTTP/WebSocket и корректное завершение.
- `Project/src/shared/` — локальные DTO и чистые функции. Между репозиториями передаются HTTP-сообщения, а не импорты исходников.

## Данные

PostgreSQL хранит пользователей, сущности, теги, вещи, активность и сведения авторизации в отдельных таблицах с документами JSONB. `Repository.read` возвращает согласованный снимок. `Repository.write` применяет изменения транзакционно; advisory lock защищает межсущностные инварианты. Ошибка callback приводит к откату. Обновления WebSocket отправляются после фиксации.

В текущем объёме сообщества фильтры и агрегаты рассчитываются по снимку. При росте нагрузки выборки и рейтинги следует перенести в SQL с индексами и нормализовать участия и результаты. Эта смена не должна менять публичный формат DTO без согласования с клиентами.

`/api/health` проверяет соединение с базой и возвращает 503 при её недоступности. Ошибка простаивающего соединения PostgreSQL не завершает API: пул удаляет сломанное соединение и создаёт новое при последующем запросе. В журналы не выводятся объекты клиента или параметры подключения.

## Авторизация

Сессия хранится на сервере; cookie содержит случайный токен, а база — его SHA-256. Production использует `__Host-`, `HttpOnly`, `Secure`, `SameSite=Lax`. Запрос входа живёт пять минут, привязан к браузерному nonce и используется один раз.

Бот узнаёт свой Telegram ID и username через `getMe` и передаёт их во внутренний API. API использует зарегистрированное имя для ссылок входа. Бот получает обновления, отправляет ответы и выполняет запросы членства по командам API через то же исходящее подключение, без входящего порта. Токен BotFather хранится у бота.

Backend проверяет Telegram ID и одноразовый запрос, затем назначает права по настройкам доступа. По умолчанию проверяется членство в разрешённых группах. При `TELEGRAM_REQUIRE_GROUP_MEMBERSHIP=false` достаточно подтверждения в боте. Администраторы в этом режиме определяются списком `TELEGRAM_ADMIN_IDS`, а остальные получают роль участника. Username пользователя остаётся контактным полем. Для привязки аккаунта используется числовой ID. Проверки членства имеют ограниченный кэш. WebSocket повторно проверяет сессии.

## Контракты и эксплуатация

Формат HTTP описан в [API-CONTRACT.md](API-CONTRACT.md). Работа с данными требует соблюдения [requirements.md](requirements.md). Dockerfile и Compose находятся в `Docker/`, локальные сценарии — в `Scripts/`, шаблон systemd — в `Deploy/`; инструкция — в [deployment.md](deployment.md). Сборка и развёртывание не требуют соседних каталогов. Персональные данные, секреты и состояние хранятся в игнорируемых каталогах либо по явно заданным внешним путям.
