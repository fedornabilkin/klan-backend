# Подготовка сервера Клана

На общем VPS с Debian или Ubuntu нужен существующий пользователь `deploy` с доступом к Docker. Скопируйте на сервер [setup-server.sh](../Deploy/setup-server.sh) из любого репозитория Клана. В каталоге с файлом выполните одну команду.

```sh
sudo bash setup-server.sh
```

Скрипт создаст в `/opt/klan` отдельные каталоги фронтенда, бэкенда и бота с правами для `deploy`, а для статики — `/var/www/klan`. В Docker он подготовит сеть `klan-production` и постоянные тома для PostgreSQL и позиции чтения бота. Запуск можно повторять.

Для отдельного сервера добавьте к команде `frontend`, `backend` или `bot`. Docker нужен для бэкенда и бота. Подготовка выполняется локально на VPS. IP и порт указываются позднее, при подключении сайта. Для входа по IP понадобится HTTPS с сертификатом на этот IP.

## Справка для установки с доменом

При установке с доменом направьте его DNS на VPS и откройте TCP 80 и 443. Для выпуска всех компонентов нужны сервер x86-64 и Compose 2.30+.

1. На сервере выполните `sudo bash setup-server.sh configure-domain`. Мастер запросит домен, токен и имя бота от BotFather, ID разрешённых групп Telegram и почту для нового сертификата. Он настроит nginx и HTTPS и сохранит пароли и параметры приложений в закрытых файлах на VPS.
2. При первом подключении GitHub на своём компьютере войдите через `gh auth login` и выполните `bash setup-server.sh github`. Понадобятся адрес и порт SSH, путь к приватному ключу пользователя `deploy`, публичный ключ хоста из вывода мастера и домен сайта.
3. В Actions → Production запустите Run workflow для `main` у бэкенда. После его успешного выпуска запустите фронтенд и бота. Последующие обновления приходят при мерже в `main` соответствующего репозитория.

Мастер настройки с доменом сохраняет настройки текущего релиза в `/opt/klan/<компонент>/shared/runtime.env`, если этого файла ещё нет. Если в GitHub остался непустой secret `PRODUCTION_ENV`, у него приоритет при выпуске. После сверки значений удалите старый secret, чтобы выпуски использовали файл сервера.

## Перенос одного компонента

Для сервера с доменом добавьте имя компонента к командам настройки, например `sudo bash setup-server.sh configure-domain bot` и `bash setup-server.sh github bot`. Последняя команда обновит SSH-параметры в GitHub только у бота.

| Компонент | Что перенести и указать |
| --- | --- |
| Фронтенд | Направьте домен на новый веб-сервер и укажите доступный ему адрес API. GitHub доставит статику. |
| Бэкенд | Сохраните `shared/runtime.env` и перенесите БД из актуального дампа. Укажите IP интерфейса частной сети/VPN и разрешите TCP 3101 только от нужных узлов. У фронтенда и бота обновите адрес API. |
| Бот | Остановите старый worker, перенесите том `klan-production-bot-state` с позицией чтения и используйте прежние токен и секрет API. Укажите частный адрес API, например `http://10.0.0.5:3101`. |

Для возврата предыдущего API выполните от `deploy` команду `bash /opt/klan/backend/current/Deploy/server-release.sh rollback`. Дампы PostgreSQL перед обновлениями лежат в `/opt/klan/backend/backups`. Восстановление базы выполняется отдельно.
