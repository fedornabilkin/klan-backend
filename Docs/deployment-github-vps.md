# Первый запуск на сервере

Используйте [setup-server.sh](../Deploy/setup-server.sh) из любого репозитория Клана. Для общего сервера нужны Debian/Ubuntu x86-64, существующий SSH-пользователь `deploy` с доступом к Docker и Compose 2.30+. Направьте DNS домена Клана на этот сервер и откройте TCP 80 и 443 для HTTPS.

1. **На сервере** сохраните файл под именем `setup-server.sh` и выполните `sudo bash setup-server.sh`. При первом запуске понадобятся домен, токен и имя бота от BotFather, ID разрешённых групп Telegram и почта для нового сертификата. Скрипт подготовит каталоги, nginx с HTTPS, хранилища и закрытые файлы настроек. Пароль новой БД и секрет связи бота с API создаются автоматически.
2. **На своём компьютере** откройте Bash (на Windows — Git Bash), войдите в GitHub CLI через `gh auth login` и выполните `bash setup-server.sh github` с той же копией файла. Введите адрес и порт VPS, путь к приватному ключу пользователя `deploy`, публичный ключ **хоста** из вывода первого шага и домен сайта. Скрипт проверит SSH и заполнит окружение `production` в трёх репозиториях. Если доступ уже настроен, пропустите этот шаг.
3. **Первый выпуск** запустите через Actions → Production → Run workflow для `main`. Дождитесь успеха бэкенда, затем выпустите фронтенд и бота. В дальнейшем мержа в `main` соответствующего репозитория достаточно. Статика собирается на GitHub, API собирается из Git на VPS, бот получает образ из GHCR.

При переходе с прежней схемы непустой GitHub secret `PRODUCTION_ENV` имеет приоритет. Скрипт сохранит настройки текущего релиза в `/opt/klan/<компонент>/shared/runtime.env`. Когда сверите их, удалите прежний secret, чтобы последующие релизы читали настройки сервера.

## Перенос одного компонента

Укажите в конце **обеих** команд один компонент, например `sudo bash setup-server.sh bot` и `bash setup-server.sh github bot`. Ключ и адрес в GitHub изменятся только у выбранного репозитория.

| Компонент | Что перенести и указать |
| --- | --- |
| Фронтенд | Направьте домен на новый веб-сервер. В режиме `frontend` укажите доступный ему адрес API. GitHub доставит статику. |
| Бэкенд | Сохраните `shared/runtime.env` и перенесите БД из актуального дампа. В режиме `backend` укажите IP интерфейса частной сети/VPN. Разрешите TCP 3101 только от нужных узлов. У фронтенда и бота обновите адрес API. |
| Бот | Остановите старый worker, перенесите том `klan-production-bot-state` с позицией чтения и используйте прежние токен и секрет API. В режиме `bot` укажите частный адрес API, например `http://10.0.0.5:3101`. |

Для возврата предыдущего API выполните от `deploy` команду `bash /opt/klan/backend/current/Deploy/server-release.sh rollback`. Дампы PostgreSQL перед обновлениями лежат в `/opt/klan/backend/backups`. Восстановление базы выполняется отдельно.
