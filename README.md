# Klan Backend

Самостоятельный API закрытого сообщества: Node.js 22.12+ / TypeScript / Express 5 / PostgreSQL 16+ / WebSocket. Репозиторий устанавливается и собирается без соседних каталогов frontend и bot.

## Запуск

Из корня этого репозитория:

```sh
npm ci
npm run dev
```

Перед запуском скопируйте `.env.example` в `.env` и задайте параметры базы, сайта и Telegram. Альтернатива — передать переменные окружения из системы запуска. Секреты не входят в Git. Локальный порт API — `3001`; готовность сервера и базы проверяет `GET /api/health`.

```sh
npm run typecheck
npm test
npm run build
npm start
```

Сборка создаёт `dist/server.js`. В `data/location-catalog/` находится публичный справочник стран и городов; он нужен при запуске и должен поставляться вместе со сборкой. Миграции выполняются транзакционно до начала приёма запросов. Ошибка миграции прерывает запуск.

Для локального просмотра есть `npm run dev:demo`: он использует `DEMO_DATABASE_URL` с отдельной базой `klan_demo` либо локальный файл состояния `.local/demo.json`, путь к которому задаёт `DEMO_DATA_FILE`. `DEMO_USER_ID` задаёт существующий внутренний ID профиля; произвольный первый пользователь не выбирается. `DEMO_ACCESS_LEVEL=admin` действует только для демонстрационной сессии. Production запрещает `DEMO_MODE=true`. Реальные данные и резервные копии не добавляются в Git.

В Windows `start-local.cmd` или `npm run local:start` запускает API в фоне из `.env`; `npm run local:status` проверяет готовность, `npm run local:stop` останавливает управляемые процессы. Необязательный `.local/postgres.json` включает запуск уже подготовленного локального PostgreSQL. Без него API использует базу из окружения. Скрипт не устанавливает PostgreSQL, не создаёт и не очищает базы, не останавливает чужие процессы. Подробнее — [локальный запуск и развёртывание](docs/deployment.md).

## Docker и сервер

Репозиторий содержит всё для самостоятельной сборки и развёртывания: Dockerfile, Compose с PostgreSQL, вариант для внешней базы, примеры окружения и unit systemd. После заполнения `.env.compose` по `.env.compose.example`:

```sh
docker compose --env-file .env.compose up -d --build
curl --fail http://127.0.0.1:3001/api/health
```

Это production-режим: нужны HTTPS origin и параметры Telegram. Внутренняя база создаётся в Docker volume, наружу не публикуется. API по умолчанию доступен на loopback `127.0.0.1:3001`; TLS и маршрутизацию сайта обеспечивает отдельный reverse proxy. Сборка использует только текущий каталог. Команды для внешней базы, Linux/systemd и связи с frontend/bot описаны в [deployment.md](docs/deployment.md).

## Границы компонентов

Бэкенд владеет данными, браузерными сессиями, проверкой членства в Telegram-группах и бизнес-правилами. Отдельный процесс bot получает обновления Telegram и передаёт их в защищённый внутренний endpoint API. В бэкенде нет второго процесса long polling.

Frontend обращается к `/api` и `/ws` на том же origin через прокси. Сервер проверяет точный `APP_ORIGIN` для изменяющих запросов. Production требует HTTPS. Сборка frontend может раздаваться внешним сервером; при явном `STATIC_DIR` API также умеет отдавать уже подготовленные статические файлы.

Контракты и чистые общие функции лежат в `src/shared/`. Это локальная копия контракта API, а не зависимость на соседний репозиторий. Изменение формата ответа нужно согласовать с frontend и покрыть проверками совместимости.

## Структура

- `src/` — API, авторизация, бизнес-операции, репозитории и тесты.
- `src/shared/` — DTO, типы доступа и чистые функции нормализации.
- `data/location-catalog/` — публичный справочник географии.
- `docs/` — контракт API, архитектура и бизнес-правила.
- `Dockerfile`, `compose*.yaml`, `deploy/` — сборка образа, PostgreSQL, сетевые и systemd-конфигурации.
- `scripts/local.mjs`, `start-local.cmd` — автономное управление локальным API и необязательным PostgreSQL в Windows.
- `AGENTS.md` — соглашения по изменению кода.

Персональные выгрузки и резервные копии не входят в Git и Docker context. Файлы развёртывания не зависят от внешнего операционного каталога.
